# 决策：Jev 零额度时阻断三版本实验

- 决策时间：2026-09-21 16:40:10 +08:00
- 状态：已确认

## 现场证据

本机已经配置非占位的 `TYPESAFE_API_KEY`，但官方 `POST /v1/systemone` 返回 `HTTP 401`。用户确认原因是 TypeSafe 账号尚未充值。

首次运行暴露出两个门禁缺口：

1. `benchmark` 只检查密钥是否存在，没有在写入 run 前验证账号可用性。
2. V2/V3 各 20 条均失败后，比较器仍从唯一无错误的 V1 中输出 `winner=mock`；这违反“三版真实运行后才产生最终赢家”的冻结规则。

失败运行保留在本地 ignored artifacts 中供排障，不作为效果证据，也不进入最终比较：

- V1：`20260921T083518Z-cbb12507`
- V2：`20260921T083621Z-5657f30d`，20/20 为 401
- V3：`20260921T083733Z-fde00249`，20/20 为 401
- 无效比较：`20260921T083733Z-f277e29d`

## 决定

1. `benchmark` 在生成任何 run 前发送一次最小 Jev 预检请求。
2. 401 等非瞬态 HTTP 错误立即失败，不重试；只对官方文档指定的 429/529 做退避重试。
3. 任一版本存在系统错误时，比较结果标记 `experiment_complete=false`、`winner=null`。
4. 账号充值并通过预检前，PR 保持 Draft，不生成最终版本选择文档。

## 验证

- 自动化测试：26 项通过。
- 零额度实测：退出码 2；新增 run 目录 0；新增 comparison 目录 0。
- 错误输出不包含完整 API key。

## 恢复条件

TypeSafe 账号充值后重跑同一条 `benchmark` 命令；只有三个版本全部无系统错误，才允许产生最终赢家。
